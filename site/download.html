Install notes

Before you install

Pre-release builds aren't code-signed yet, so your OS will ask you to confirm. Here's what to expect.

Windows: SmartScreen

Because the installer isn't signed yet, Windows shows "Windows protected your PC".

  1. Click More info.
  2. Click Run anyway.
  3. The first time you turn on sync, allow ClipTrail through the firewall on Private networks.

Linux: .deb or AppImage

  • .deb: sudo apt install ./ClipTrail_*.deb pulls in libxdo3 for paste-back.
  • AppImage: chmod +x ClipTrail_*.AppImage, then run it.
  • Wayland: capture works on compositors with data-control (KDE Plasma, Sway, Hyprland). GNOME lacks it, so ClipTrail only sees copies while an X11 app has focus. Paste-back is X11-only: on Wayland the picker copies and you press Ctrl V.

macOS: Gatekeeper

  1. Open the .dmg and drag ClipTrail to Applications.
  2. On first launch macOS blocks the unsigned app. Open System Settings → Privacy & Security and click Open Anyway.
  3. For paste-back, allow ClipTrail under Privacy & Security → Accessibility (Settings in the app links straight there).

Android: sideloading

When v0.1 ships, install the APK from the release (allow "Install unknown apps" for your browser or file manager), then follow the in-app checklist: accessibility service, restricted settings, battery, tile. Samsung needs a few extra steps.

System requirements

WindowsWindows 10 or 11, 64-bit (x64). Uses the Microsoft Edge WebView2 runtime, which Windows 11 includes; the installer fetches it on older systems.
Linuxx86_64 with WebKitGTK 4.1 (Ubuntu 22.04 or newer, Debian 12, Fedora 38+). X11 for paste-back; Wayland capture needs a data-control compositor.
macOSmacOS 12 or newer, universal (Apple silicon and Intel). Experimental: capture and paste-back work; paste-back needs Accessibility permission.
AndroidAndroid 10 or newer (arm64), coming with v0.1. Tested first on Samsung One UI.
SyncDevices on the same local network (Wi-Fi or LAN) that can reach the hub on TCP port 47821.

Checksums: releases don't publish SHA-256 files yet; signed builds and checksums are planned. Every release is built by GitHub Actions from the tagged source (release workflow).
