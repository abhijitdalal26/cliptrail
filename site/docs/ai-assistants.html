Docs / Using ClipTrail

AI assistants (MCP) New

Ask your AI assistant for something you copied, in plain words: "find the Postgres connection string I copied in March". It searches your ClipTrail history and can put the clip back on your clipboard. It works with the assistant you already use, through the Model Context Protocol (MCP).

Only on your computer. The assistant starts ClipTrail on your laptop (cliptrail --mcp) and talks to it directly over standard input and output. ClipTrail itself never talks to any cloud: there's no account, no ClipTrail server and no open network port. Clips you copied on your phone are included, because they sync to the laptop.

Set it up in one click

  1. Open ClipTrail on your computer and go to Settings → AI assistants.
  2. Turn on Let AI assistants search my history. ClipTrail checks that its server answers, then adds itself to every AI app it finds on your computer (keeping a backup of each settings file). To pick apps one by one, use Choose apps.
  3. Restart the assistant if it was open, and ask. Once it has used ClipTrail, Settings shows "… last used it 2 minutes ago", so you know it really works.

The AI app must be installed on the same computer as ClipTrail. That is what keeps your history safe: the app starts ClipTrail on your computer and talks to it directly, with no internet server in between. Web chats in a browser (claude.ai, chatgpt.com, gemini.google.com) can't connect, by design. ClipTrail only connects apps that are really installed: it looks for the program itself, not leftover settings folders.

Manual setup

Every MCP app takes the same thing: start ClipTrail with --mcp. Copy config in Settings gives you this block with the right path for your computer:

{
  "mcpServers": {
    "cliptrail": {
      "command": "C:\Users\you\AppData\Local\ClipTrail\cliptrail.exe",
      "args": ["--mcp"]
    }
  }
}

On Linux the command is /usr/bin/cliptrail (the .deb) or the path of your AppImage. For Claude Code from a terminal: claude mcp add --scope user cliptrail -- <path to cliptrail> --mcp.

Without the desktop app (servers, scripts), build the standalone server instead: cargo install --locked --git https://github.com/abhijitdalal26/cliptrail clipd-mcp, and use clipd-mcp as the command. Both read the same history folder; set CLIPTRAIL_DATA_DIR to use another one.

What the assistant can do

The server offers eleven tools. Eight only read; the other three are small conveniences that change nothing you already have. There is no tool to delete or edit a clip.

ToolWhat it does
search_clipsFull-text search, with optional filters for kind, source app, device (your phone or this computer), pinned only and a date range (from / to as YYYY-MM-DD). Returns summaries.
recent_clipsNewest clips first, same filters, no query: "what did I copy recently?"
get_clipOne clip's full body by id or unique id prefix.
clip_statsTotals: clips per kind, pinned count, top source apps.
list_source_appsThe apps your clips came from, handy for filtering.
day_countsClips per calendar day for the last N days (default 30, up to 365).
pin_clipPin or unpin a clip so it stays at the top and is never cleaned up.
copy_to_clipboardPut a clip back on your system clipboard so you can paste it. Refuses sensitive clips.
get_current_clipboardWhat's on your clipboard right now ("fix the error I just copied"). Text that looks sensitive is withheld.
save_to_historySave text the assistant made for you (a command, a link) into your history, marked as from "AI assistant", so you can find it later on the laptop and the phone.
list_devicesYour devices (this computer, your phone) and how many clips came from each, for "what did I copy on my phone?"

Things to ask

  • "Find the Postgres connection string I copied in March." Searches with a date range.
  • "What code did I copy from VS Code yesterday?" Filters by kind, source app and date.
  • "Get that link ready to paste." Searches, then puts the match on your clipboard.
  • "Pin the clip I copied an hour ago." Looks at recent clips, then pins it.
  • "How much did I copy this week?" Uses the stats and per-day counts.
  • "What did I copy on my phone today?" Filters by device.
  • "Explain the error I just copied." Reads your clipboard right now.
  • "Save that command to my clipboard history." Keeps it for later, on every device.

ClipTrail also tells the assistant, when it connects, to look in your history whenever you mention something you copied, so you rarely need to say "use ClipTrail". Apps that support MCP prompts (Claude Desktop, Claude Code as / commands) also get two ready-made ones: Find something I copied and What did I copy today?

Privacy and safety

  • Local only. ClipTrail sends nothing anywhere for this. Clips go from your history to the assistant program running on your own computer. With a local model (LM Studio), nothing leaves your machine at all.
  • Sensitive clips are withheld. One-time codes, API keys, private keys and card numbers are masked in ClipTrail. The assistant gets metadata and ••••••, never the body, and copy_to_clipboard refuses them. Copies from password managers were never saved in the first place.
  • Read-mostly. It can search, read, pin, copy back and add new text. It can't delete or edit anything.
  • What the assistant reads goes to your AI provider. The server is local, but the assistant usually isn't. Any clip it reads becomes part of your conversation with Claude, Cursor's model or whichever service you use, under that provider's terms. Ask for specific things rather than "summarise everything I copied", and remember that ordinary text can still contain private details even when it isn't flagged as sensitive.
  • You choose. Nothing is connected until you turn it on (or add the config yourself). Turning it off, or Disconnect under Choose apps, removes it again.

What about ChatGPT?

Not supported, and not planned for v1. ChatGPT's connectors call a remote MCP server over HTTPS and sign-in; they can't start a program on your computer. ClipTrail keeps your history on your devices, end-to-end encrypted, so serving it to a cloud chat would mean sending your plaintext clips to a hosted service. We think the local boundary is the right one. Clients that start a program on your own machine work today.

Troubleshooting

  • The assistant finds no clips. The server reads the data folder of the user it runs as. If you use CLIPTRAIL_DATA_DIR or --data-dir for the app, set the same value in the server config ("env": { "CLIPTRAIL_DATA_DIR": "..." }).
  • Settings says connected but never "last used". Quit the assistant completely (also from the tray) and open it again; assistants only load their tools at start. The assistant says the server failed: restart it after connecting. If you moved or reinstalled ClipTrail in another place, click Connect again so the path is updated. To check by hand, run cliptrail --mcp in a terminal: it waits for input, so no error means it works (Ctrl C to quit).
  • Connect says the settings file isn't plain JSON. Some apps allow comments in their settings file; ClipTrail won't rewrite those. Use Copy config and paste the block in yourself.
  • A clip's body is ••••••. It's classified as sensitive; open it in the ClipTrail app instead.
